# 新居住权益系统整体实施计划（2026-09-20）

状态：整体计划建议。进展：M1-A2（运营闭环）、M1-A3（结算业务闭环）与 **M1-A4（运行验收）已完成**——异常恢复/告警实测/性能/备份恢复/回退/操作手册全部交付，见 [M1-A4 运行验收报告](../verification/newliving-commerce-m1a4/README.md)；A2/A3 缺口（会员顺延、先行赔付）已在本轮补齐并回归。M1-B1/B2 仍未启动。

基于 v1.9 需求、现有 M1-A 实施和最新用户要求。本计划更新阶段顺序与范围，原技术计划保留为历史设计依据。后续遵循原全站风格，复用主站账号、订单入口和售后工单；当前贵阳数据为演示数据，不代表正式商户签约或真实资金试点城市已经变更。

## 总目标与当前状态

建立可追溯、可运营、可对账的新居住权益业务：商品配置与发布 → 浏览购买／兑换 → 会员与发券 → 预约履约 → 核销计账 → 账期结算 → 回执对账；退款、到期、误核销和赔付追偿走完整逆向流程。

M1-A 已交付正式账号及 MySQL 底座、配置审核与发布、用户与管理页面、贵阳演示商品、演示购买、兑换码基础功能、会员与卡券、二维码核销、主站订单与售后关联。最新验收为 39 项专项、136 项 IAM、16 项线上只读检查。上述数量对应已有交付，不代表结算或真实资金能力已经验收。

## M1-A3 结算实施拆分

1. 核查主站已有结算、财务和商户主体能力，形成复用清单；订单和工单继续使用现有关联关系，禁止另建用户可见的平行订单系统。
2. 冻结计算契约：成本模式、逐券分摊、佣金依据及上限、尾差、渠道归属、补贴／兑换资金来源、会员费分配、退款口径。v1.9 中不同段落存在的参数差异须明确裁决并形成版本；不得直接把示例数值作为生产规则。
3. 建立逐券账务：核销事实、商户应结、渠道子佣金及平台净留存具有共同来源和规则快照；未核销部分独立追踪。记录采用追加和关联冲回，不能覆盖历史账项。
4. 建立结算批次：默认双周账期按已确认规则配置，支持复核、异常冻结、审批与执行。每条明细只能进入一个有效结算占用，防止跨批次重复结算。
5. 建立执行状态与查单：业务应结、批准执行、外部处理中、实际到账分别表达；UNKNOWN 只查询原请求，不换指令重复付款。机构负责实际资金预占和执行，平台记录指令及状态。
6. 建立逆向流程：部分退款、未核销到期原路退回、误核销撤销、已结算后退款，以及赔付和追偿。关联原资金来源和原账项，保证用户可退额度及费用承担正确。
7. 建立对账：订单／核销业务事实、业务账、执行记录与机构账单逐笔匹配；差异具备分类、责任人、证据、处理过程与关闭依据。
8. 完成交付页面：运营应结／批次／审批／执行／退款冲回／差异管理；商户账单与到账；推广端佣金及结算状态；用户退款进度。接口、权限、审计和页面一并验收。

## 资金验收标准

沿用 v1.9 的六项断言，并各有应失败的反例：

- 贝壳佣金＝渠道子佣金合计＋贝壳净留存。
- 比例模式核销基数＝商户应结＋贝壳佣金；固定成本模式按自己的显式规则校验。
- 订单资金分配＝实付－退款＋补贴，使用一致的统计时点并保留资金来源。
- 已付＋有效预占不超过可付；明细不可跨批次重复占用。
- 每组借贷平衡，已记账项不能覆盖更新。
- 赔付关联应收代偿或保证金抵扣；未核销退款不记为赔付。

必须覆盖：全核销、部分核销、部分退款、到期退款、会员多批次、跨账期、规则改版、同事件重复100次、回执乱序、超时未知、失败重试、已结算后退款、无推广归属、资金来源差异，以及万级核销明细批次生成。每例保留输入快照、预期／实际金额、规则版本与证据。

## 无资金与真实到账的区别

现有演示订单继续零实付、零实际佣金。M1-A3 使用独立测试库／明确隔离的测试账验证非零金额，仿真回执和账单均标记测试，不能混入线上真实余额、可提现金额或实际到账统计。

M1-A3 完成代表结算业务引擎与流程完成隔离验收。M1-B1 必须取得机构沙箱证据；M1-B2 必须取得真实回执和账单。缺少外部接口、合同或审批时，记录为未验收依赖，不能用模拟成功替代对应阶段完成。

## 发布门与阶段 Goal

真实收款开启前按 v1.9 核对：G1 商户授权、供给和产能；G2 已审批的成本分配及资金来源；G3 退款、到期、误核销、停业及追偿责任；G4 权限、并发、幂等、机构查单对账和恢复证据。暂停新增销售须保留已有权益查询、售后及存量处置。

建议下一轮 Goal 仅覆盖 M1-A2—M1-A4：在保持无资金模式和现有全站风格的前提下，完成四端运营、结算业务与运行验收，交付可运行代码、可操作页面、可重跑测试、账务样例、截图及操作手册。分阶段报告，全部必需项通过后才将此 Goal 标记完成。

M1-B1、M1-B2 和 M2 分别作为后续阶段目标管理，不能因当前无资金 Goal 完成而同时标记完成。
