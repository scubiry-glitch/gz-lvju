## 2. 目标与完成定义

**用户已选择：M0 无资金联调版，实现并验证频道与四端核心流程。Goal 已启动。**

**用户补充约束：页面 UI 规范参考此前全站风格，不改变既有视觉体系。** 新页面复用全站 CSS、字体、品牌色、卡片、按钮与导航；仅补所需布局和状态样式，不重新设计品牌主题。

本轮已选目标为 M0 无资金联调版：用户从新居住频道进入券包或会员方案，通过明确标识的测试流程生成测试订单和权益，完成预约、商户核销，并在推广端及管理端观察逐券佣金与异常处理结果。为后续真实交易保留独立 commerce 模块与接口契约。

本轮验收终点为M0实现与验证，不把演示结果当成M1验收。后续真实交易试点须额外通过第5节的全部条件。

M0 完成需同时具备：可运行的本地版本、频道接入、四端核心业务、自动化与浏览器验证证据、可复现的启动/验收说明、明确列出的真实交易缺口。未实现项不能通过文案或静态数字充当完成。

## 3. M0 验收清单

| ID | 目标 | 可执行验收与通过标准 |
|---|---|---|
| AC01 | 频道接入 | 首页生活服务权益入口可到券包、会员及我的卡券；保留原分类入口；新增页面在导航总览可达，无失效链接 |
| AC02 | 商品区分 | 券包和会员独立商品；券包可直接购买；会员显示自身期限和赠券期限；未知城市无商品时正确空态 |
| AC03 | 购买前知情 | 商品及确认页展示逐券供应商、门店、门槛、有效期、预约可得性与到期退回说明；未批准规则不能真实销售 |
| AC04 | 测试隔离 | 测试环境与订单明确标记，不出现真实支付成功承诺；不会调用生产收款、代发、真实通知或修改生产数据 |
| AC05 | 幂等订单与发券 | 连点/同请求重复仅产生一个订单结果；重复测试支付事件仅发一批券；同SKU两张券具有不同实例ID；发券失败可按原批次补偿 |
| AC06 | 会员生命周期 | 开卡与发券分别呈现状态；续费产生新批次；会员到期不自动撤销尚有效赠券 |
| AC07 | 预约正确 | 产能10且已约满时第11单失败；未预约券不占产能；取消释放；改期失败保留原预约；已有有效预约不因门店满额拒绝核销 |
| AC08 | 核销正确 | 预览不核销；确认后同券最多一份有效核销；重复请求返回原结果；过期/退款冻结/无权门店拒绝，并显示明确原因 |
| AC09 | 逐券确认 | 未核销不产生已确认佣金；仅核销A测试券时展示商户15984分、推广1998分、平台净留1998分；剩余79920分列未核销负债 |
| AC10 | 归属与四端视图 | 分享归属由服务端或隔离测试服务校验；无推广归属佣金为0；商户只见本商户应结、推广员只见本人佣金，消费者不见平台利润 |
| AC11 | 售后与到期 | 卡券及订单有售后入口与状态；未核销到期进入原路退回任务；退款与核销互斥；赔付和未核销退回分开记录 |
| AC12 | 机构状态语义 | 模拟机构付款超时显示UNKNOWN/查询中；不得改请求ID重付；镜像余额有来源，不能称平台实存资金 |
| AC13 | 权限真实性 | 后端按身份及对象范围检查，跨用户/商户访问失败；模拟角色切换仅测试环境可用；不以隐藏菜单替代检查 |
| AC14 | 视觉与错误状态 | 关键移动页在390px、桌面工作台在1440px检查，无横向溢出或遮挡；正常/空/无权/失败均可验证；提供截图证据 |
| AC15 | 可维护及回归 | 独立commerce边界、接口/字段说明和启动命令可复现；新源代码不被静态服务公开；原首页/导航/业务相关回归通过 |

验收必须注明测试后端类型。内存或文件测试适配器通过只证明流程及部分逻辑，不证明 MySQL 事务、数据库并发、正式SSO或真实资金能力。数据库与机构级验收留给 M1，不混淆证据等级。

## 4. 执行顺序与证据

1. 范围与契约：冻结M0页面、身份与订单契约；确定隔离测试适配器及生产默认关闭方式。
2. 垂直闭环：频道入口→详情→测试下单→卡券；先验AC01–AC05。
3. 履约：预约/改期→商户核销→订单记录；验AC07–AC08及跨商户拒绝。
4. 会员与推广：开通/续费、签名分享、逐券佣金和机构付款状态；验AC06、AC09–AC10、AC12。
5. 逆向及管理：补发、退款、到期、赔付分类、审计与权限；验AC11、AC13。
6. 浏览器及回归：验AC14–AC15，整理执行结果、截图、失败与遗留。

证据拟归档 `docs/verification/newliving-commerce/`：验收结果表（逐AC标PASS/FAIL/BLOCKED/NOT RUN）、命令与退出状态、关键截图、接口样例及未决依赖。每条结果带代码提交或版本标识；有FAIL或核心项未执行不得宣布目标完成。

## 5. M1 真实交易附加验收

- 正式用户身份校验及对象授权实测，生产没有演示登录或测试成功回调入口。
- MySQL独立连接并发测试覆盖库存、预约、核销/退款互斥、重复批次；迁移与恢复演练通过。
- 持牌机构支付、原单查单、分账、双周批付、退款、代发及逐事件账单实测通过；UNKNOWN不重付。
- S01–S30、E01–E08与六个资金不变量全部通过，包含失败反例，证据可追溯。
- 逐券商务规则、账户/合同、门店产能、会员资金分配及售后参数经过审批；不能将999元示例和模拟费率当真实合同。
- 到期自动退回与已核销赔付追偿分别演练；赔付准备金为自有资金，人工兜底有姓名与SLA。
- G1–G4记录齐全，监控、灰度和存量售后回退可执行；单机构渠道的延期/完成状态明确披露。

## 6. Goal 运行纪律

按所选目标持续推进，遇到普通实现失败先定位修复。外部依赖未到位时继续独立模块、测试和文档，不虚构成功。只有选定范围全部完成并有验收证据，才能标记 Goal complete。

每次进度区分“文档已完成”“代码已实现”“验证已通过”“外部仍依赖”四种状态；范围变更同步本文及验收表。
