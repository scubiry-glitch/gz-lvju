# M1-A 正式业务底座与管理页面

用户确认：实施M1-A、补齐相关管理页面，前端按正式标准交付；延续全站风格。测试域名 `sytest.meizu.life` 为实际验收入口，现有分支继续开发。

## 本轮交付

1. MySQL独立commerce表及可审计迁移，账号中心正式会话，对象级商户/门店权限；关闭M0测试身份和测试支付入口。
2. 平台管理：经营概览、商户审核、门店与核销人员、券SKU、报价/规则双审、券包组包及发布、会员方案、库存及产能、订单/发放、预约/核销、售后工单、审计记录。
3. 商户管理：本商户资料、门店/人员、SKU及报价提审、预约/核销、订单与售后协同。平台审批入口不向商户放行。
4. 正式用户页面：可公开浏览，登录后访问本人订单/卡券/会员/预约/售后。推广端使用正式身份和来源校验，资金操作显示尚未开通。
5. 支付仍关闭；不允许前端按钮或管理员将订单改成已支付。内部履约入口只由后续已验证支付适配器调用，集成测试在独立数据库验证发券/核销。

## 验收门

| 编号 | 标准 |
|---|---|
| A01 | 服务重启后业务记录保持；迁移可重复执行，失败可恢复，不修改原业务表 |
| A02 | 原账号中心登录会话可用；匿名401、跨账号/商户/门店403；全局旧API Key和演示会话拒绝 |
| A03 | 商户、门店、人员、SKU、报价、券包、会员具备新增/编辑/校验/提审/复核/发布及状态查询；申请人不能自审 |
| A04 | 已审批规则/商品版本不可覆盖；改动回草稿并生成下一版本；已售快照保持 |
| A05 | 多SKU库存预占全有或全无；失败不残留占用；超时订单释放；并发不超卖 |
| A06 | 日期产能独立落库；预约/改期/取消互斥；满额拒绝；已预约核销不重复占产能 |
| A07 | 同券最多一次有效核销；核销与售后冻结互斥；逐券计算与事实同事务；重复发放不增加券 |
| A08 | 四端列表/详情/表单具备加载、空态、失败、无权、校验、危险操作确认、成功反馈；手机390px/桌面1440px可用 |
| A09 | 导航与全站总览同步，页面风格复用既有规范，无测试身份切换和模拟成功按钮 |
| A10 | sytest域名可访问正式页面/API；测试/真实支付入口关闭，未知路由返回JSON错误而非首页 |
| A11 | 数据库并发、正式会话、权限及浏览器回归有证据；公开页面不泄露账户、合同、供货价、佣金或审计数据 |

真实支付、分账、提现、真实退款、机构渠道及完整财务冲回属于M1-B；本轮完成相关配置/明细/受理页面与权限接口，不伪造外部能力。
