## 会员口径

v1.9 §3.3、§5.4.7、§5.4.8：一期只配置L1一个卡种，对外统一名称“新居住会员”，999元/年；赠送保洁、维修、搬家、旅居、报告各一张。礼包是独立商品，会员通过package_id绑定。

五种会员权益保留独立SKU，不能擅自把频道现有保洁时长、搬家车型或房产评估改称已经谈妥的会员服务。现有保洁/维修/搬家/评估SKU只作为供应候选；旅居暂无适用于该方案的明确供给。会员券的供应商、门店、规格、报价、有效期均保留待确认。会员有效期与券有效期独立。

文档中199.80/133.20/277.50/333.00/55.50元分摊，以及20%/50%佣金示例均为演算参考，不写成已批准商务条件；也不将M01—M12模拟主体当成已签约商家。本次13家来自专题实际商品关联，与文档的12家模拟招商数量没有强行一一对应。

## 草稿与审批

所有69份配置以draft写入，created_by=0标记系统初始化，未伪造提交人、复核人、合同、联系电话、商户报价、库存承诺或审批快照。21个券商品的可售库存为0（未开放配额），不代表供货成本为0。未确认财务字段保持null，管理详情显示“待确认”。

这些配置可在以下入口查看：

- [商家管理](https://sytest.meizu.life/screens/commerce-admin-merchants.html)
- [券商品](https://sytest.meizu.life/screens/commerce-admin-skus.html)
- [券包配置](https://sytest.meizu.life/screens/commerce-admin-packages.html)
- [会员方案](https://sytest.meizu.life/screens/commerce-admin-plans.html)

资料完善顺序：商家合同及联系方式 → 实际门店和产能 → 券规格/供货报价/规则 → 券包价格与分摊 → 会员绑定。各层完成后按已有流程提交、由不同账号复核并发布。草稿不进入公开销售目录；购买和资金入口保持关闭。

管理详情新增来源与初始化时缺项说明。编辑未绑定供应商的初始化草稿时允许首次补齐商家/门店关联；已经确立的归属不可借初始化标记改成其他商户。人工补齐不丢弃原来源信息。

## 执行与验证

```bash
node scripts/commerce/initialize-topics.cjs          # 生成清单，不写数据库
node scripts/commerce/m1a-test.cjs --initialization --browser
node scripts/commerce/initialize-topics.cjs --apply
```

脚本使用事务和数据库命名锁；每份配置在commerce_events记录稳定seed_key和来源校验和。重复执行仅复用已初始化记录，不覆盖人工修改，不重复创建。遇到依赖丢失整批回滚，不删除已有记录。该脚本用于初始化，不自动同步后续专题改动。

- `plan.json`：本次配置内容、来源与依赖；不含凭据。
- `receipt-*.json`：实际执行回执与实体ID。
- `test-results.json`：独立MySQL库中的6组初始化验收。
- `topic-package-detail.png`、`membership-detail.png`：隔离库浏览器截图。
- 四端及业务回归结果记录在 `../newliving-commerce-m1a/results.json`。
