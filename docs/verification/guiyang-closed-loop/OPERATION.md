# 贵阳生活服务频道 · 权益闭环操作说明

适用范围：sytest 预览域名（`https://sytest.meizu.life`）上的无资金演示环境。所有购买/兑换均为零资金演示，页面与接口均有明确标识。

## 1. 入口与角色

| 端 | 入口 | 角色/权限 |
|---|---|---|
| 用户端（C 端） | `/juzhu-commerce.html?city=贵阳`（首页/会员/我的）、`/juzhu-vouchers.html`（选券）、`/juzhu-voucher.html`（权益/卡券详情） | 新居住个人账号（账号中心登录） |
| 推广端 | `/juzhu-promoter.html` | 个人账号即可分享并查看本人归因 |
| 商户中心 | `/screens/commerce-merchant.html`（工作台）、`-appointments`（预约）、`-redemptions`（核销）等 | `commerce.merchant.read/write/redeem` + 绑定商户 + 门店核销人员授权 |
| 运营中心 | `/screens/commerce-admin.html`（概览）、`-exchanges`（兑换码管理）、`-stats`（运营统计）等 | `commerce.admin.read/write`，复核需 `commerce.admin.review` 且提交人不能自审 |
| 账号与权限 | `/screens/account-center.html` | 账号、角色、数据范围、审计唯一管理入口 |
| 主站订单/工单 | `/juzhu-jiazheng-orders.html`（我的订单）、`/juzhu-order-progress.html?order=`（工单进度） | 本人会话 |

登录统一走账号中心（`BZF_SESSION_TOKEN` 会话）。防爆破：连错 5 次锁 30 分钟。

## 2. 兑换码管理（运营）

入口：运营中心 → 「兑换码管理」。

- **批量发码**：点「批量发码」→ 选择已发布的演示商品（单品券/券包/会员）→ 填兑换有效天数（1–90）与数量（1–200）→ 生成。**明文码仅在本结果窗口完整展示一次**，请立即复制保存；系统只存哈希，审计不写明文。
- **查询**：按商品类型/状态（未兑换、已兑换、已过期、已停用）/商品名称筛选；顶部汇总给出四态计数。**筛选「已兑换」即为兑换记录**，含兑换账号、兑换时间与到账订单。
- **停用**：未兑换/已过期的码行内点「停用」→ 立即不可兑换、记入审计；已兑换的码不能停用（409）。重复停用幂等。
- **规则**：每个码仅可兑换一次；商品版本更新后旧码拒绝兑换（提示联系发放方换码）；**兑换时库存不足会整体回滚，码保持未兑换状态**（不吞码），库存恢复后可再次兑换；已停用/已兑换/已过期均拒绝并给出明确原因。
- 发码请求带 `Idempotency-Key`，网络重试不会重复发码。
- 商品行内的「生成兑换码」按钮等价于数量为 1 的快速发码。

## 3. 商户履约（商户核销员）

入口：商户中心 → 「预约管理」「核销记录」。

- **当日预约**：「预约管理」默认只看**今天**（可改日期或清空看全部），每条含服务日期、服务项目、客户与状态；商户工作台首屏有「今日预约」计数。
- **核销（两段式）**：「核销记录」页点「核销卡券」：
  1. 扫描用户二维码（扫码枪粘贴或摄像头识别，内容 `NLV1:<券编号>:<动态码>`），或在下方手动录入券编号 + 动态码——两种方式最终走同一接口；
  2. 点「**核对服务（不核销）**」→ 预览服务项目、门店、预约日期、客户与本商户应结；**预览无任何副作用**；
  3. 核对无误后提交「确认保存」完成核销；核销后券状态、预约状态与逐券分账一次落库。
- **失败原因**（页面直接展示，接口带结构化错误码）：
  | 提示 | 说明 |
  |---|---|
  | 未获该门店核销授权 | 操作人不在该门店核销人员名单 |
  | 不允许访问其他商户的数据 | 跨商户访问被拒 |
  | 卡券已使用、冻结或过期 | 重复核销 / 售后冻结 / 已过期 |
  | 核销码无效或已过期 | 动态码 2 分钟有效，超时需用户刷新 |
  | 请先完成预约 / 仅可核销当日预约 | 履约顺序约束 |
- 用户端「出示核销码」支持二维码 + 复制券编号/动态码 + 2 分钟倒计时与刷新。

## 4. 用户端（C 端）

- **购买**：选券页/详情页 →「演示购买」→ 勾选无资金演示知悉 → 权益到账「我的卡券」（会员另开通会员有效期）。
- **兑换码兑换**：「我的」→「兑换码兑换」→ 输入码 + 勾选知悉 → 到账。
- **我的卡券**：顶部 chips 按 全部 / 可用 / 已使用 / 已过期 筛选（带计数与空态）；券详情展示有效期、编号、使用条件、所属订单与履约记录（预约/核销）。
- **预约/改期/取消**：可用券 →「预约服务」选日期（受提前量、名额、有效期约束）；「服务预约」页可改期、取消（取消释放名额）。
- **售后**：券详情/卡券列表 →「申请售后」（服务协助 / 未使用退款）；退款申请冻结券并取消未履约预约；处理结果在「售后服务」与主站工单进度页同步可见。未使用券到期自动冻结并生成原路退款待处理单（演示单标注无实际退款）。
- **订单追踪**：主站「我的订单」→ 权益订单详情展示「履约进度：到账 → 预约 → 核销」逐券链路。

## 5. 推广（推广员）

- 商品卡片 →「生成分享链接」→ 7 天有效签名链接；购买页带 `ref` 回跳并校验（篡改/过期/版本不符拒绝）；自购不记归属。
- 「推广记录」展示归因订单（拆分演示/真实）、有效核销与已确认佣金；演示单佣金恒为零且与真实交易分开呈现；提现未开放。

## 6. 运营统计与异常处理

- 运营中心 →「运营统计」：发放、订单（演示/真实）、预约（含今日）、核销分账、兑换码四态、售后八态六组汇总；**近期失败记录**列出最近 20 条业务失败（接口 + 原因），累计数可定位。
- 重试纪律：所有写操作幂等（同 `Idempotency-Key` 重试返回原结果，不同内容 409），重试不会重复发放/核销/占用库存。
- 双人复核：配置（商户/门店/商品/规则/券包/会员/核销人员）保存草稿 → 提交 → 另一复核账号审批 → 发布；提交人不能自审。

## 7. 运维命令

```bash
# 服务（127.0.0.1:38780，nginx 仅转发 /api/commerce/v1/）
systemctl restart sy-commerce-preview.service     # 启动时自动执行迁移
curl -H 'Host: sytest.meizu.life' http://127.0.0.1:38780/api/commerce/v1/meta

# 验收
node scripts/commerce/m1a-test.cjs --guiyang-demo --browser   # 隔离库全量（临时库自动清理）
node scripts/commerce/m1a-iam-regressions.cjs [--main-reuse]
node scripts/commerce/m1a-public-smoke.cjs                    # 线上只读
node scripts/commerce/live-closed-loop-check.cjs              # 线上登录态（发码后全部停用）
node test_index_boot.js && node test_static_guard.js

# 数据（幂等，仅补缺）
node scripts/commerce/seed-guiyang-demo.cjs --apply
node scripts/commerce/link-main-systems.cjs
```

部署：`node scripts/commerce/install-preview.cjs`（保留配置备份、健康检查、权限目录刷新）。回退恢复上一个已验证版本，不删业务表。
