# 设计：家政商家联调手册

日期：2026-08-17

## 1. 背景与目标

家政版块已与来来（vendor 41）联调通过。未来新商家入驻时，将由其他人接手联调工作。需要一个联调手册，让接手人无需口头交接即可完成新商家联调。

手册需包含：测试库地址、数据如何配置、测试服务器地址、日志如何查看、联调步骤和方法等详细信息。**密码等敏感信息不得写入手册**（只标注获取途径）。

## 2. 已确认决策

- **存放位置**：仓库根目录（与 `api_doc.md` 并列）；api_doc.md 面向商家、联调手册面向内部接手人
- **数据配置方式**：手册给出 INSERT SQL 模板 + 字段逐项说明（与现有 41/42 接入方式一致），不写配置脚本
- **商家侧清单**：手册包含"商家需要准备/实现的事项"清单，接手人可直接转达给新商家

## 3. 手册结构（8 章）

### 1. 手册目的与适用对象
定位：内部联调人员（开发/运营）使用；与 api_doc.md 分工说明。

### 2. 环境信息一览
- 测试服务器：`http://49.232.103.71:8765`（部署目录 `/projects/beike`）
- 测试库：MySQL `62.234.26.57:3306` 库名 `juzhu`（本地与测试共用同一实例；账号密码在 `juzhu/.env` 的 `JUZHU_DB_*`，手册不写）
- 本地启动：`cd juzhu && python3 server.py`（默认 8765 端口）
- 发布脚本：`bash publish_test.sh`（rsync 同步代码 + 重启测试服务器；脚本内含服务器凭证，手册不写）
- 出站 IP 白名单：GR 侧调用商家接口的出站 IP 需商家加白名单（实际 IP 从日志"IP无权访问-x.x.x.x"获取）

### 3. 数据配置（新商家入驻）
- 关键表说明：jz_vendors（商家主数据，type/city_ids/hmac_key/url_link/order_detail_url）、cities（4 城）、jz_skus（24 个平台标准品 SPU）、jz_products（商家产品，由商家通过 vendor 接口维护）、gr_orders（订单）
- 新商家 INSERT SQL 模板 + 字段逐项说明
- hmac_key 生成命令：`openssl rand -hex 32`（64 位 hex，与商家约定）
- 提醒：密钥配置改 jz_vendors 表后需重启 server 生效（进程内懒加载缓存）

### 4. 商家侧工作清单（转达商家）
- 提供 HMAC 密钥（64 位 hex）
- 实现 api_doc.md 第 2-4 章：HMAC 签名、订单状态回调、产品管理接口
- 提供 api_doc.md 第 5 章两个接口：URL Link 生成接口、订单详情查询接口
- 将 GR 测试服务器出站 IP 加入商家接口白名单

### 5. 联调步骤与方法
顺序：商家信息收集 → GR 侧数据配置 → 商家接口实现 → 签名自测（sign_test.py）→ 全接口联调（test_vendor_api.py，22 请求）→ 下单全链路（wechat-link → url_link → 回调）→ 订单详情同步 → C 端验证（test_gr_my_orders.py）。
含：回调状态机说明（pending→paid→assigned→serving→completed；cancelled 终态；vendor_oid 一致性）、测试数据造单示例。

### 6. 日志查看与问题排查
- 本地：`/tmp/juzhu_server.log`；测试服务器：ssh 登录 49.232.103.71 后 `tail -f /tmp/beike_server.log`
- `[平台→商家]` 出站请求日志（URI/参数/返回）；JUZHU_LOG_DETAIL 开关
- 常见问题排查表：401 签名失败、IP 白名单拒绝、SSL 证书、vendor_oid 不匹配、状态未推进、详情未覆盖（静默失败）、配置不生效

### 7. 联调完成验收清单
逐项 Checklist：签名验签通过、产品 CRUD 通过、5 种回调状态正确落库、下单生成链接、C 端订单可见、详情同步生效、日志无异常。

### 8. 安全约定
- 手册不含密码/密钥；凭证获取途径（juzhu/.env、publish_test.sh）
- 密钥不进 git（.gitignore 屏蔽 *.key / .env*）
- vendor 对外接口不返回 hmac_key 等敏感字段（平台已做剥离）

## 4. 准确性验证（文档任务替代 TDD）

提交前对手册中每个地址/命令/SQL 模板逐项实测：
1. 测试库地址可达、库名正确（已实测 SHOW TABLES 正常）
2. INSERT SQL 模板在测试库真实执行验证（插入测试商家后回滚删除）
3. sign_test.py / test_vendor_api.py 可运行（已实测通过）
4. 日志路径存在（本地 /tmp/juzhu_server.log 已实测）
5. 各表列名与 SQL 模板一致（已实测 DESCRIBE）

## 5. 范围边界（不做什么）

- 不写配置脚本（已决策 SQL 模板）
- 不写真实密码/密钥/服务器凭证
- 不修改任何代码与数据库 schema
- 不重复 api_doc.md 的接口协议细节（引用即可）
