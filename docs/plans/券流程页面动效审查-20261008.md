# 券流程页面与动效审查（2026-10-08）

## 主流程

选券商品 → 查看适用范围与规则 → 购买或活动领取 → 我的卡券 → 选择住宿或本地服务 → 结算页报价与用券 → 支付或零现金提交 → 履约、核销与售后。

这里把迪士尼动画原则当作信息反馈的设计约束。迪士尼动画工作室将 timing、staging、anticipation、follow-through、secondary action 等列为让动作清晰可信的原则（[官方说明](https://www.disneyanimation.com/process/animation/)）。券是资金权益，动效必须服从金额和状态的准确表达。

| 原则 | 页面问题 | 本轮处理 |
|---|---|---|
| Staging（清晰呈现） | 价格、抵扣、应付与下一步混在一起；占用中的券落入历史 | 结算单独显示券抵与现金应付；卡券钱包增加“占用中”筛选，并把占用中的券留在当前列表 |
| Anticipation（预期动作） | 查券异步执行时没有提示，用户会以为没有券 | 住宿与本地服务结算页显示查询中、无适用券、查询失败和重试入口；领取页先说明限额与步骤 |
| Timing 与 Slow in/Slow out（节奏、缓入缓出） | 金额变化缺少反馈 | 报价明细与状态以约 220–240 ms 的轻微位移和淡入呈现；保持最终金额静止，减少反复闪动 |
| Follow-through（动作后续） | 用券后只看到“已使用”，不易找到目标订单 | 卡券详情显示用券订单、券抵金额、现金应付和履约状态，可继续打开目标订单 |
| Secondary action（次要动作） | 说明文字可能抢过主操作 | 适用范围、退款归属与核销说明放在次级信息层；主按钮保持领取、选服务或提交订单 |
| Appeal / Squash and stretch（亲和力、形变） | 把资金权益做成庆祝动画容易造成误解 | 保留轻微按压反馈和票券状态色；不使用庆祝粒子、自动跳价或夸张弹跳 |

## 验收重点

- 更换房型、日期或间数时，旧券报价立即失效，随后重新查询；不能用旧券金额提交。
- 查券失败时明确说明，保留按原价提交与重试两条路径。
- 直接兑换显示签约兑付价，金额抵用显示整张券抵扣；两种情况都显示本单现金应付。
- 活动赠券仅展示领取人的用券权益；原订单付款与退款归属仍由服务端控制。
- 所有新增动效遵守 `prefers-reduced-motion`，页面状态同时用文字和色彩表达。

## 浏览 → 下单 → 购买 → 核销复核（同日续审）

| 阶段 | 动画原则转成的交互要求 | 本次查出的断点与处理 |
|---|---|---|
| 浏览 | **Staging**：卡面只表达一条明确的详情入口；**Anticipation**：焦点可见，键盘操作结果可预测 | 选券卡原为可点 `article`，但不能用键盘打开；补为单一 `role="link"` 焦点入口，支持 Enter/空格，并用静态视觉按钮避免嵌套交互。 |
| 下单 | **Staging / Timing**：报价先呈现结算价、券抵和现金应付，查询中与报价失效必须有文字 | 住宿和本地服务现有查券、失败重试、提交重报价仍沿用前轮实现；本轮补齐下单后回看金额，避免用户离开结算页后只看到原价。 |
| 购买 | **Follow-through**：动作完成后清楚区分“待支付”“支付成功”和“券全额覆盖”；结果提示应接上订单 | 演示购买的成功弹层会替换原弹层，统一弹窗提交逻辑现识别替换情形；零现金住宿与本地服务结果页明确显示用券成功。H5 待入住列表包含零现金用券订单，并显示券抵与现金应付。 |
| 核销 | **Anticipation**：商户先看到核对信息才可最终提交；**Follow-through**：客户出示码后能看见核销完成 | 商户页以前只写了“先核对”，按钮并未锁住；现在核对成功前禁用提交，券码变化后重新核对。客户出示码弹窗每 5 秒查本人卡券状态，核销后撤下动态码、显示结果和核销记录入口。 |
| 全程节奏 | **Timing / Appeal**：只用短促、低强度反馈；减少动态效果时完全静止 | 保留现有 220–240 ms 状态进入反馈；会员卡组与回顶按钮的 JS 平滑滚动跟随 `prefers-reduced-motion`。不把券到账或核销做成夸张庆祝动画。 |

验证：前端脚本语法检查、旧版住宿与本地服务零现金结果页两条模拟浏览器流程、H5 零现金结果页、演示购买弹窗替换、选券卡键盘打开、商户核销先核对后提交及客户核销状态更新均通过；H5 Vite 构建通过。当前构建使用 `morph-shim`（缺少内网私有 `@ke/morph`），真实支付收银台和商户现场扫码仍需在联调环境走查。
