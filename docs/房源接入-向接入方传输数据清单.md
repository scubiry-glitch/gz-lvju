# 房源接入 · 订单外发数据清单

| 项 | 内容 |
|---|---|
| 依据 | `screens/property-intake-api.html`（房源开放接口 v2.2）及线上出参实现 |
| 我方 | 新居住平台 |
| 对方 | 白名单运营商、持有方商家（HMAC 接入方） |
| 范围 | 预订订单：查单响应，以及推送到商家 `webhook_url` 的订单事件 |
| 日期 | 2026-10-12 |
| 口径 | 信息安全合规以 **我方 → 对方** 的订单内容为主 |

签名摘要 `sign`、时间戳 `timestamp` 随报文出现，用于验签；商家密钥本身不出现在任何外发报文中。

---

## 1. 外发通道

订单交给对方，只有两条路。

| 通道 | 方向 | 触发 | 对方怎么拿到 |
|---|---|---|---|
| 查单与动作回执 | 我方 → 对方 | 对方调用 `bookings/list`、`bookings/detail`、`bookings/confirm`、`bookings/cancel` | 响应 JSON。只返回该商家名下的订单 |
| 订单事件 | 我方 → 对方 | 客户下单、支付完成、客户取消 | 我方向商家配置的 `webhook_url` 发 `POST` JSON |

推送未配置地址则不发。对方对推送的 HTTP 应答正文，我方只看状态码（2xx 视为送达），不解析、不入库。

两个出口的字段不同：

- **查单**（`bookings/list`、`bookings/detail`）：带联系人，手机号为掩码。
- **订单事件**（`booking.created` / `booking.paid` / `booking.cancelled`）：订单体不含联系人姓名、不含手机号。

---

## 2. 个人信息

| 数据 | 外发形态 | 出现位置 |
|---|---|---|
| 住客手机号 | 11 位时为掩码：前 3 位 + `****` + 后 4 位，例如 `139****5678`。长度不是 11 位时按库存原值返回 | 仅 `bookings/list`、`bookings/detail` |
| 住客手机号明文 | 不外发 | — |
| 住客姓名 | 按库存原文返回 | 仅 `bookings/list`、`bookings/detail`。公开文档示例里的「张**」是示意，线上出参不做姓名脱敏 |
| 住客姓名、手机号 | 不包含在订单事件里 | `booking.created` / `booking.paid` / `booking.cancelled` |
| 我方账号 `user_id` | 外发 | 仅 `bookings/detail` |
| 支付与结算协议快照 `payment_config_snapshot` | 不外发（详情组装时删除） | — |
| 商家密钥 | 不外发 | — |

---

## 3. 订单（全量）

客户在 C 端提交预订后产生。金额在下单时锁定：逐晚价（日历覆盖价优先，否则默认夜价）合计 × 间数。佣金按当时费率写入快照，之后调价不追溯。

订单状态：`pending`（待确认）→ `confirmed`（已确认）或 `cancelled`（已取消，终态）。

支付状态 `pay_status` 由交易方式决定，与频道无关：

| 取值 | 含义 |
|---|---|
| 空 | 在线预订。商家确认后线下收款 |
| `unpaid` | 在线支付单已创建，尚未支付。此状态不可确认 |
| `paid` | 已支付，可以确认 |
| `coupon_funded` | 券已覆盖应付现金 |
| `refunding` | 退款处理中 |
| `refunded` | 已退款 |
| `partially_refunded` | 部分退款 |
| `expired` | 待支付超时，订单取消并释放房态 |
| `closed` / `closing` | 支付单关闭中或已关闭 |

### 3.1 订单列表 `bookings/list`

我方按字段清单查询后返回，单次最多 200 条。对方可按 `status`、`pay_status`、`project_id` 过滤；过滤条件是对方传入的查询条件，不是订单内容。

响应外壳：`code`、`message`、`total`、`list[]`。`list[]` 每一项如下。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 平台订单主键。确认、拒单用这个 id |
| `order_no` | string | 订单号，例如 `BKG-RENTAL-00036` |
| `project_id` | int | 房源 id |
| `project_name` | string | 房源名称 |
| `unit_id` | int 或空 | 户型 id。空表示整栋 / 不限房型 |
| `channel` | string | `rental` 租赁住宿 / `minsu` 惠居民宿 / `newhouse` 新房 / `resale` 二手 / `trade` 卖旧买新 |
| `checkin` | string | 入住日，`YYYY-MM-DD` |
| `checkout` | string | 离店日，`YYYY-MM-DD`（不含当天） |
| `nights` | int | 入住晚数 |
| `rooms` | int | 预订间数，缺省 1 |
| `price_total` | number | 订单金额，单位元 |
| `commission_rate` | number | 下单锁定的佣金费率，单位 %。未单独配置的商家按全局基准，缺省 10 |
| `commission_fee` | number | 下单锁定的佣金金额，单位元 |
| `status` | string | `pending` / `confirmed` / `cancelled` |
| `pay_status` | string 或空 | 见上表 |
| `pay_method` | string 或空 | 支付方式。在线支付完成后才有值 |
| `pay_at` | string 或空 | 支付完成时间 |
| `payment_expires_at` | string 或空 | 在线支付截止时间 |
| `created_at` | string | 下单时间 |
| `contact_name` | string | 住客姓名原文 |
| `contact_phone` | string | 住客手机号掩码 |

列表不返回：`user_id`、城市、佣金以外的券拆分、退款单号、幂等键、更新时间。

### 3.2 订单详情 `bookings/detail`

对方传入订单 `id`。我方校验归属后返回 `booking` 对象：订单表当前行的全部列，另加 `project_name`，手机号按同一规则掩码，并删除 `payment_config_snapshot`。

因此详情比列表多出下列字段。

| 字段 | 类型 | 说明 |
|---|---|---|
| `city_id` | int | 房源所在城市 id |
| `owner_vendor_id` | int | 订单归属商家 id，与签名商家一致 |
| `user_id` | string 或空 | 下单用户在我方账号体系中的标识 |
| `updated_at` | string | 订单最近更新时间 |
| `idempotency_key` | string 或空 | 客户下单时的幂等键，用于我方防重复下单 |
| `request_hash` | string 或空 | 下单请求内容摘要，用于我方防重复下单 |
| `coupon_minor` | int | 券抵扣额，单位分。未用券为 0 |
| `cash_due_minor` | int 或空 | 现金应付，单位分 |
| `coupon_application_id` | string 或空 | 用券申请单 id |
| `paid_payment_order_id` | int 或空 | 我方支付单 id |
| `latest_refund_id` | int 或空 | 最近一笔退款单 id |
| `refund_status` | string 或空 | `refunded` / `partially_refunded` / `refunding` |
| `refunded_at` | string 或空 | 全额退款完成时间 |

详情同样包含 3.1 的全部字段（`id`、`order_no`、`project_id`、`project_name`、`unit_id`、`channel`、`checkin`、`checkout`、`nights`、`rooms`、`price_total`、`commission_rate`、`commission_fee`、`status`、`pay_status`、`pay_method`、`pay_at`、`payment_expires_at`、`created_at`、`contact_name`、`contact_phone`）。

明确不下发：`payment_config_snapshot`（下单时冻结的结算协议，含资金路由，只留在我方库内）。

### 3.3 确认、拒单的回执

对方只传入订单 `id`，不回传住客资料或金额。我方回执如下，不重复整单。

确认成功：

| 字段 | 说明 |
|---|---|
| `code` / `message` | `0` / `success` |
| `id` | 订单 id |
| `order_no` | 订单号 |
| `status` | `confirmed` |
| `ok` | 在线支付单确认时附带，值为 true |

拒单 / 取消成功：

| 字段 | 说明 |
|---|---|
| `code` / `message` | `0` / `success` |
| `id` | 订单 id |
| `order_no` | 订单号 |
| `status` | `cancelled`，或关单尚未完成时仍为原状态 |
| `pay_status` | 线下单为空；已支付单为 `refunding`；关单中为 `closing`；用券单为 `closed` |
| `pending` | 退款或关单尚未完成时为 true |
| `ok` | true |
| `idempotent_replay` | 订单已经是取消态、重复调用时为 true |

商家自己拒单不会再推 `booking.cancelled`。超过支付时限自动取消会推，`cancel_by` 为 `expired`。取消会释放已占的间夜。

### 3.4 订单事件（我方主动推送）

推送体：

| 字段 | 说明 |
|---|---|
| `event` | 事件名，见下表 |
| `vendor_id` | 商家 id |
| `order` | 订单摘要。字段按事件固定，少于查单 |
| `timestamp` | 毫秒时间戳 |
| `sign` | 签名摘要 |

| event | 何时推送 | `order` 内字段 |
|---|---|---|
| `booking.created` | 客户提交预订单 | `id`、`order_no`、`project_id`、`unit_id`、`channel`、`checkin`、`checkout`、`nights`、`rooms`、`price_total`、`status`（`pending`）、`pay_status`、`transaction_mode` |
| `booking.paid` | 在线支付完成 | `id`、`order_no`、`project_id`、`unit_id`、`checkin`、`checkout`、`nights`、`rooms`、`price_total`、`status`、`pay_status`（`paid`）、`payment_id` |
| `booking.cancelled` | 客户取消，或超过支付时限自动取消。线上、线下都在订单变为已取消时推送；已支付的客户取消此时为退款处理中，不等退款到账。商家自己拒单不推 | `id`、`order_no`、`project_id`、`unit_id`、`channel`、`checkin`、`checkout`、`nights`、`price_total`、`status`（`cancelled`）、`pay_status`、`cancel_by`（`customer` 客户取消，`expired` 超时未支付） |

`transaction_mode`：`booking` 在线预订（确认后线下收款），`payment` 在线支付。

`payment_id`：我方支付单 id，只出现在 `booking.paid`。

这三条事件的 `order` 都不含：`contact_name`、`contact_phone`、`commission_rate`、`commission_fee`、`user_id`、券拆分、退款单号。`booking.cancelled` 也不含 `rooms`、`transaction_mode`。

送达：超时 5 秒；非 2xx 按 5 秒 / 30 秒 / 120 秒重试 3 次后放弃。对方应以 `bookings/list` 对账。`booking.paid` 由持久任务投递，进程重启不会丢。
