分阶段评估 · 用户价值-产品 / 平台运营 / 城市运营

每个阶段一个 tab；三个视角各自回答「为什么做、做什么、靠什么落地」
壹
交易闭环 MVP —— 能住、能付、能结2026.09 – 2026.11 中 · 约 10 周 + 2 周运营调优
📍 硬节点：10/15 一期呈现 · 支付完成后 2 周内全面上线（0903 纪要）· 康养季前完成
频道：rental + minsu渠道：贝壳 APP / 小程序 单渠道 城市：贵阳单城（0903 纪要 · 10/20 后评估扩容）房源双模式：在线预订 / 400 电话咨询
👤 用户价值 · 产品C 端 / 业主 / 商家
  • 旅居客：房源展示与图集、详情、筛选（区域/价格/房型/彩贝标签）
  • 旅居客：房态日历 + 最短连住；未开通在线预订的房源一键 400 虚拟号拨商家（实时绑号、不缓存）
  • 旅居客：下单 → 支付（微信 + 银行存管）→ 取消/退款 → 订单状态机 → 电子凭证
  • 营销基础：新人首单券、拉新券发放（券位与核销埋点预留，差别化营销的起点）
  • 业主：批量导入、上下架、收益看板雏形、结算账单
  • 商家：订单确认、房态维护、按晚预订开关（缺省 false=仅电话）
⭐ 平台运营中台能力建设
  • 商家入驻全流程易低估：签约、保证金、结算账户收集、HMAC 密钥发放、入驻进度看板
  • 客服与人工干预后台必答题：改单、退款审核、投诉工单、紧急下架（投诉处置率指标的工具底座）
  • 结算引擎：一期费率暂定 10% 平台费用 + 折扣设计（0903 纪要），配置化不硬编码——差别化佣金的策略地基；发票与对账位预留
  • 埋点与数据基线：浏览→下单→支付漏斗；一期跑出基线，二期目标基于基线定
  • 安全基线：敏感路径拦截、密钥只进 .env、演示种子与真实数据隔离
🏙 城市运营试点落地
  • 招商工具当产品需求冷启动：快速录入向导、批量照片上传、AI 收益估算当业主招商钩子
  • 两级目标：标杆聚焦泉湖公园特色民宿（0903 纪要），50 套跑通全链路；10/20 后评估贵阳 BD 目标再定扩量节奏
  • 政府背书杠杆：王市长六件事督办、相关局长沟通（0903 纪要政府线）；BD 地推团队是供给瓶颈，配额到位
  • G 端只读汇总：接入数 / GMV / 结算量 —— 监管维度，不看一线工单（视角红线）
  • 等保三级测评启动周期长：政府数据接口的前置条件，一期就要排队
✅ 出口标准（承诺 · 试点期可控）10/15 一期呈现 · 支付完成后 2 周内全面上线 · 支付成功率 ≥98% · 结算准确率 100%、0 资损 · 400 接通率 ≥90% · 泉湖标杆房源全链路贯通 · 漏斗/接通/退改基线产出 · 交易上线前完成对应小程序类目资质。未达标 → 延期 / 缩范围 / 重做试点，不进二期。
📈 上限假设（非承诺）200 套房源接入、GMV 规模依赖招商传导与政策背书，仅作试点目标不作推广承诺；二期转化目标以一期基线为准，现在不拍数字。
⚠ 风险与依赖：① 资金合规——一期即银行存管，不做资金池；② 招商不及预期→缩到 1 城 50 套先跑通；③ 小程序类目资质（ICP/EDI）是交易上线前置条件，必须在一期出口前拿到；等保三级测评可与后续整改并行推进。

⭐ 平台运营中台能力建设
  • 内容中台：PGC → UGC 流程 + 内容审核（照骗/虚假宣传/广告法用词）
  • 保险对接：只与持牌险企 API 对接，平台仅投保分发，不碰精算、不碰牌照
  • 客服 SLA 工具：首响 ≤3 分钟的目标看板与排班
  • IM 合规：记录留存、敏感词、未成年人保护
  • 流量承接：贝壳 APP 主入口流量位排期在二期前谈定，内容上线即有承接面
🏙 城市运营试点落地
  • 康养季运营：温泉 / 苗年侗年专题页 + 首场券大促，银发客群专属活动（康养季主力人群）
  • 内容本地化：贵阳/黔东南周边地点种子扩到试点全城，笔记与房源双向挂载
  • 站外投放试点：抖音/小红书小预算试投，验证内容→详情 CTR 再谈放量
  • VR 拍摄组织：按城市排拍摄档期（供应商集中拍摄降本）
  • 春节值班：康养高峰冻结期客服与 400 兜底排班
✅ 出口标准（承诺）IM 人工首响 ≤3 分钟 · 高彩贝房源 VR 覆盖 ≥60% · 取消险投保率 ≥30% · 周边内容绑定房源 ≥80% · 详情→下单转化率对比一期基线的提升幅度达标。
📈 上限假设（非承诺）站外内容带来的 MAU / 站外流量规模依赖社媒平台与投放预算，属上限假设；内容转化数据仅作放量决策依据。
⚠ 风险与依赖：① 保险精算与牌照——只做分销不分保；② 内容审核人力不足→先 PGC 收口，UGC 后置灰度；③ 春节冻结期发布窗口收窄→插件功能须 1 月上旬全量。

👤 用户价值 · 产品C 端 / 服务者
  • 旅居客：可查「持证管家」——L 等级、持证编号、验真、责任险兜底，住得放心留得住

  • 服务者：实名持证上岗、按级派单、T+7 分账、信用分月度滚动升降级
  • 服务商：L5 商业认证、团队管理、批量承接
⭐ 平台运营中台能力建设
  • 认证发证链路：培训中心 → 题库机考 → 统一发证（持证编号 + 验真 + 派单资格）
  • T 端接入：培训机构招生 / 排课排考 ⇄ 中台考务审批 / 结业核发 / 课程认证
  • 派单引擎：按等级分发 + 履约跟踪；信用引擎：客户评价→信用分→流量权重
  • 等级挂钩分账贯穿：派单分成随 L 等级与信用分浮动——等级越高分成越高（差别化佣金第二级）

📜 合规线（贯穿，一期启动）

  • 等保三级：一期启动测评、三期完成拿证——政府数据接口前置条件
  • ICP 经营许可 / EDI：在线交易类目与小程序审核门槛
  • 电商法 §38：经营者资质核验是法定义务，四期「房源评级」按义务对待
  • 个保法：实名信息最小化存储、虚拟号录音与 IM 留痕合规
  • 发票与对账：一期预留发票位，四期完善

⚙ 机制保障

  • 北极星唯一：试点城市入住间夜数；其余全降为护栏指标
  • 旺季冻结窗口：7/1–8/31 与 1/15–2/20，只允许热修与增量 SKU
  • stage-gate 评审会：每期出口，产品+运营+政府方三方；结论只有「过 / 缩范围 / 延期」
  • 运营调优周：每期上线后 2 周只修问题不加功能
  • 演示/产品分层：静态原型是演示层，真小程序独立选型（Taro/uni-app/原生），边界写进文档

♻ 存量复用（不重复造）

  • 频道模型（rental/minsu、旅居=rental+「旅居」tag）、房态日历三态、INSURANCE_TYPES
  • spots 周边内容、_jzapi 家政总线、RATING_DIMS 频道评级口径
  • 商家 HMAC 开放接口（五期分销商接入直接复用）
  • 权限注册表（新 admin 路由必登记）与账号中心
  • newhouse/resale 频道 = 五期置业导购的现成底座

👆 用户体验 · 全年主线

  • 各期主题：一期首订链路（≤4 步、失败兜底 400）→ 二期体验分层（适老化 / 内容 / IM）→ 三期信任可视化（验真卡 / 评级）→ 四期服务过程可视（工单 / 管家进度）→ 五期全渠道一致

  • 性能预算：首屏 ≤2s、图片走缩略图管线；每期上线前体验走查关键路径

🏡 供给运营 · 全年主线
