一

六个负责角色 · 三类组织

组织三分类：平台定规则管资金 · 城市管拓展与商家 · 集中化管标准执行与客户服务——每个环节的主责（R）都落在这六个角色上
🏢 平台 定规则 · 管资金
📋 产品运营平台 · 规则与体验
定规则、建工具、管体验——审核执行已下沉集中化，平台只留标准与仲裁
负责范围
  • 入驻 / 上架准入标准与审核 SOP（制定）
  • 频道与类目管理（rental / minsu）
  • 彩贝评级口径、复核与仲裁
  • 交易链路健壮性（幂等 / 对账 / 0 资损）
  • 埋点漏斗、北极星看板、体验主线
  • 券与活动策略、抽查规则制定
不做什么：不执行具体审核（归房源管家）、不背商家业绩
💰 结算运营平台 · 资金与结算
商家的钱袋子线——从对账到分账到扣罚
负责范围
  • 支付对账日清、差异熔断跟进
  • 商家 T+7 结算与分账执行
  • 退款原路执行与到账跟踪
  • 保证金收退、违约金 / 赔付扣结
  • 发票与结算凭证协同（三期完善）
不做什么：不定费率（策略归产品运营）、不碰资金池（银行存管）
🏙 城市 管拓展 · 管商家 · 管本地内容
🏬 商家运营城市 · 含商务职能
城市侧商家第一责任人——招商、拓展、实勘一条线
负责范围
  • 招商签约与商务条款（含原商务职能）
  • 入驻辅导（资料 / 密钥 / 结算账户 / 保证金）
  • 房源实勘 / 拍照 / VR 拍摄排期
  • 商家培训、活跃度与分层运营
  • 房态价格催办与治理、房源焕新
  • 商家违约违规处理与考核（响应率 / 接单率）
  • 异业 / 渠道合作接洽（银行 · 社媒 · OTA）
不做什么：不代商家维护房态与价格；不对外承诺未经产品运营确认的 SLA 与排期
📝 内容运营城市 · 内容与种草
内容即获客——属地笔记与专题的经营人
负责范围
  • PGC 内容生产排期与选题（周边玩法 / 攻略）
  • 内容审核报送（真实 / 版权 / 广告法，与产品运营共判口径）
  • 专题组织、笔记挂房源
  • 内容数据回流（内容→详情 CTR）
  • UGC 灰度准备（二期）
不做什么：不发布未审核的商家素材；不做交易类通知营销
🎯 集中化 共享中心 · 管标准执行与客户服务
🏠 房源管家集中化 · 审核中心（管「货」的标准执行）
商家审核 + 房源审核集中办理——供给质量的守门人
负责范围
  • 商家资质审核（入驻复审、黑名单校验；受理工作台作业——服务认证中台 · B 分组）
  • 房源上架审核（AI 图像查重防照骗 / 图质 / 用词合规）
  • 彩贝评级评定与动态调级执行
  • 驳回 → 整改 → 复审闭环留痕
  • 验真 / 评级卡片信息维护（公示口径）
不做什么：不实地实勘拍摄（归商家运营）、不定准入标准（归产品运营）
🧑‍💼 客源管家集中化 · 客户与品控中心（管「客」）
客户全程陪伴 + 品控抽查——从咨询到客诉一个出口
负责范围
  • 400 / IM 咨询接待与推荐带看、协单催付
  • 取消 / 退款首接协调
  • 客诉：首接定级 → 闭环跟进（星云客服承接 400 进线）
  • 抽查：品控抽查（房源与实拍一致 / 服务履约），结果进评级与商家考核
  • 入住关怀、回访与复购；收藏 / 联系人场景催转化
不做什么：不绕开平台私下交易（虚拟号通话留痕合规）
二

正向主链路 · 商家入驻到用户支付

7 个环节 · 每个环节讲清「范围 / 特点 / 谁负责 / 时限」；卡片底部缩略图 = 原型页快照，点击直达原型
📌 一期口径（0903 纪要）：下单 · 支付 · 房源展示含照片 · 400 电话 —— 10/15 一期呈现 · 支付完成后 2 周内全面上线 · 一期仅贵阳单城 入驻开通 T+2 房源首审 T+1 IM 人工首响 ≤3min 客诉首响 2h 退款审核 T+1 · 到账 T+3 支付对账 T+0 日清
① 商家入驻招商 · 签约 · 开通
② 商家审核集中审核 · 准入
③ 上架房源实勘 · 录入 · 房态
④ 房源审核真实 · 合规 · 评级
⑤ 用户浏览筛选 · 详情 · 收藏
⑥ 下单校验 · 锁房 · 协单
⑦ 支付存管 · 凭证 · 对账
①商家入驻资料齐 T+2 开通
功能范围
  • 招商洽谈 → 注册开通（登录账号 / 联系人 / 短信验证）
  • 上传资质（营业执照 / 经营许可 / 法人实名，OCR + 人工复核）
  • 提交即落库受理（vendor_onboarding）——凭申请单号 + 手机号随时查进度
  • 保证金缴纳（档位待确认）→ 结算账户登记
  • 商家后台开通 + HMAC 密钥审核通过后线下下发（不落明文）
特点：全程网办；商家可选 API 对接（HMAC 开放接口）或后台手工录入，两条路同标准
负责商家运营 · 招商签约与开通主责（含商务）产品运营 · 准入标准与费率
②商家审核T+2 出结果
功能范围
  • 工商 / 许可核验、黑名单与风险校验 —— 线上 OCR + 线下复核；核验清单在受理工作台留痕（p-vendor-onboarding，真实流程：申请落库 → 受理 → 通过 / 驳回）
  • 频道准入（rental / minsu）→ 管理台「项目编辑器 · 频道」字段（projects.channel）；类目与经营范围 → 平台类目字典
  • 结算费率：基准 10%（0903 纪要）随申请单落库、折扣受理时核定 —— 差别化费率引擎一期配置化
  • 受理状态机：待受理 → 核验中 → 通过 / 驳回（终审不可变更，全程留痕 + 审计）
  • 驳回理由留痕 + 申诉通道
特点：资质核验是电商法 §38 的平台义务，不是卖点；一次审核 + 存续期年审
负责房源管家 · 集中审核主责产品运营 · 标准 / 复核仲裁商家运营 · 补材料协同
注：真实流程已上线 —— 申请落库（vendor_onboarding）→ 受理工作台受理 / 核验 / 通过 · 驳回（权限点 vendor.onboarding.review + 审计留痕）；通过后密钥（vendor_id + hmac_key）按线下流程发放；审核闸 = projects/create 建稿 → projects/status 上架。
③上架房源实勘后 T+1 录入
功能范围
  • 位置 / 房型 / 面积 / 价格、照片 ≥8 张 + VR
  • 设施自查表（按彩贝 5 维）、周边玩法挂载
  • 房态日历 + 最短连住 + 按晚预订开关（stay_bookable）
  • 400 直通电话配置（未开通预订 = 仅电话咨询）
特点：双模式接入降门槛；批量导入 + PMS/API 直连；一房一档，未过审不上架、缺省不对外
负责商家运营 · 主责（实勘 / 拍摄 / 录入）房源管家 · 上架审核衔接
④房源审核首审 T+1
功能范围
  • 信息真实性（AI 图像查重防照骗）、图片质量
  • 用词合规（广告法）、价格与房态一致性
  • 彩贝评级预打分 → 上架发布
  • 驳回 → 整改 → 复审闭环留痕
特点：审核集中化——房源管家执行、产品运营定标准与仲裁；首审 + 客源管家存续期抽查（结果进评级调级）
负责房源管家 · 主责审核客源管家 · 存续期抽查产品运营 · 标准 / 仲裁商家运营 · 整改协同
⑤用户浏览首屏 ≤2s
功能范围
  • 频道首页 / 列表筛选（区域 / 价格 / 房型 / 彩贝）
  • 房源详情：图集 / 房态日历 / 周边玩法 / 验真卡
  • 收藏与最近浏览、分享、渠道落地页
特点：真房源口径全端统一；内容种草挂房源（笔记 → 详情）；未开通预订房源展示 400 直通
负责客源管家 · 主责推荐带看产品运营 · 转化体验 / 埋点内容运营 · 种草内容
⑥下单漏斗日监测
功能范围
  • 日期 / 房态校验（可订晚 + 最短连住）→ 下单即锁房态
  • 入住人信息（实名最小化）、价格明细、优惠券核销
  • 订单创建幂等防重；400 咨询可由客源管家代客预填
特点：下单锁房 + 幂等是交易健壮性第一关；协单过程 IM / 通话留痕可追溯
负责客源管家 · 主责协单产品运营 · 流程 / 埋点
⑦支付成功率 ≥98% · 对账日清
功能范围
  • 收银台（微信 + 银行存管 · 贵州银行，贵阳城市对接、支付协议 9/18 出版本）、支付超时关单与房态释放
  • 电子凭证发送；支付对账 T+0 日清、差异熔断
特点：资金存管不入平台池，入住确认后 T+7 结算商家；支付失败降级 400 人工指引，不引导线下私下收款
负责产品运营 · 链路健壮性结算运营 · 对账日清客源管家 · 催付 / 支付协助
三

逆向与异常流程 · 运营在场的四个场景

正向链路决定能不能成交，逆向链路决定会不会砸口碑——每个场景都写明运营角色怎么接
↩ 取消订单（用户发起）审核 T+1 · 到账 T+3
用户申请› 客源管家首接（挽留 / 记录原因）› 按取消政策自动算退款档› 大额 / 特殊人工审› 原路退回› 房态自动释放› 商家结算同步扣减
  • 取消政策分档（免费截止日：待确认）；购取消险享宽松退改（二期保险联动）
  • 退款进度全程可视（订单详情 + 订阅消息）
负责客源管家 · 首接协调产品运营 · 政策 / 人工审核商家运营 · 商家侧确认结算运营 · 退款执行
⚠ 商家取消 / 无法履约（供给违约）客户触达 ≤30min
商家取消› 平台告警› 客源管家 30min 内联系客户› 同级 / 就近房源安置› 差价按平台规则兜底› 商家违约记录与处置
  • 违约梯度：首次提醒 → 扣分降权 → 暂停接单 → 清退（旺季从重）
  • 安置房源由客源管家闭环，差价规则由产品运营定
负责商家运营 · 治理主责客源管家 · 客户安置产品运营 · 兜底规则结算运营 · 违约金扣结
📞 客诉（分级处理）首响 2h · 一般 48h 结案
400 进线 / 订单 / 12345 转办（星云客服承接）› 客源管家首接定级› 一级 · 一般：48h 结案（补偿 / 券）› 二级 · 重大：仲裁 + 整改 + 日清上报› 三级 · 疑难：联席仲裁 72h› 结案回访 → 整改进商家考核
  • 一级 · 一般（服务瑕疵 / 咨询类）：客源管家 48h 内结案，补偿 / 券闭环
  • 二级 · 重大（涉安全 / 资金 / 政府转办）：2h 响应、产品运营仲裁 + 商家整改 + 管理层日清上报
  • 三级 · 疑难（跨方争议：费率 / 赔付 / 多商家）：结算运营 + 产品运营联席仲裁，72h 出结论
  • 客服由星云客诉团队承接 400 进线（0903 纪要）；工单化全程留痕，投诉处置率进监管大屏（护栏指标）
负责客源管家 · 主责（首接 → 闭环）产品运营 · 仲裁 / 规则商家运营 · 商家整改结算运营 · 补偿执行
🛠 入住中异常（房不符 / 设施故障）响应 1h · 方案 4h
客户上报› 客源管家受理› 商家运营现场核实› 服务工单（维修 / 保洁 / 管家）› 换房或赔付方案› 回访 + 房源整改记录
  • 服务工单真实链路已打通：App「我的 · 服务工单」→ 工单详情页 → 工单池（p-service-demand，演示总线 + API 并行）→ 派单 → 服务者推进
  • 整改记录回流彩贝评级（动态调级的输入）；工单体系与家政频道共用总线，不另建体系
负责商家运营 · 现场核实整改主责客源管家 · 受理与客户安抚房源管家 · 结果复审进评级产品运营 · 换房 / 赔付标准结算运营 · 赔付执行
四

体验支线功能 · 影响转化的「周边工程」

产品运营 · 主责客源管家 · 回访名单
🔔 消息通知一期交易 · 二期营销
  • 范围：订单 / 支付 / 退款进度、商家回复与降价提醒、客诉进度；小程序订阅消息 + 短信兜底
  • 特点：重要交易通知不依赖单一通道；频控与免打扰，营销类默认关闭
产品运营 · 主责客源管家 · 知会
