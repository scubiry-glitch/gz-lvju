1. 角色与权限准备

统一结算中心的页面本身不带权限，所有校验都在服务端；一个账号能看什么、能做什么，由账号中心的功能权限 + 数据权限（scope）共同决定。

在账号中心（账号与权限 → 数据权限）配置

  • 功能权限（挂在角色上）：settlement.fund.read / fund.write / fund.adjust / fund.review、settlement.approval.act、settlement.policy.write / policy.review、settlement.statement.read / generate / export / confirm / dispute / review、settlement.external.*、settlement.accrual.adjust。
  • 数据权限 scope（挂在账号角色上）：level:'all' 且不配 party_ids = 可见全部主体；配置了 party_ids:[…] = 仅名单内主体（即使 level=all 也会被名单收窄）。改完保存会吊销该账号会话，重新登录生效。
为什么结算主体下拉里没有"全部"？下拉=「有业务痕迹的主体 ∩ 你有权限的主体」。选「全部授权主体」只是不按主体过滤查询，列表仍逐行做行级权限——scope 之外的主体一行都不会出现。要扩大可见范围，去账号中心改 scope，或在「账户与协议」补主体准入。

双人复核原则贯穿全域：规则、绑定、账户、协议、审批、异议，申请人与复核人必须是两个账号；自审批在服务端直接 403。

2. 主体与协议准入（授权主体从哪来）

「结算主体（party）」是法律结算主体标识（如 demo-stay），不是商户 id。一个主体要出现在结算中心，必须在「结算工作台 → 账户与协议」完成准入，全部是草稿 → 另一人复核批准：

① 业务主体绑定→② 机构收款账户→③ 商户结算协议→④ 进入结算与出账
准入项关键字段说明
业务主体绑定业务来源（booking / jiazheng / commerce / identity / platform）· 业务主体编号 · 法律主体标识把业务系统里的真实编号（如商家/服务商 id）映射到法律主体。表单里提供「查询已有主体 / 查询已绑定业务编号」链接，录入前先查重。
机构收款账户支付机构 / 环境 / 商户号 / 资金合同号 / 币种 / 已核验能力机构未开通的操作不能勾选；站内来源、商户、平台账户须同机构同币种。
商户结算协议计算方式（比例 / 固定成本+独立佣金）· 履约确认 · 原款存放方式 · 收款契约 · 分账契约版本预订（民宿/长租）履约固定为「按订单离店日期」；等待时间等在结算规则配置。

主体只有出现以下任一业务痕迹才会进入主体目录：已批准绑定、已批准账户、业务上下文（有过订单）、出账策略。

三业务的履约确认与支付渠道（结算协议准入时选定）

业务履约确认方式支付渠道资格时间
生活权益（券）权益有效核销（COUPON_REDEMPTION）站内收银台券核销即取得资格，可另加协议「履约后结算等待（小时）」
生活服务客户验收确认（CUSTOMER_ACCEPTANCE，客户在订单页点击确认）站内收银台；外部小程序（wechat_mini，仅对账不付款）客户验收即取得资格，可另加协议「履约后结算等待（小时）」
预订（民宿/长租）按订单离店日期（BOOKING_CHECKOUT_DELAY，在结算规则配置 N 与账单日）站内收银台；线下收款（仅对账）离店 + N 天，可选账单日批量

跨法律结算主体的权益商品必须按主体拆单；每个结算单位会按协议拆成商户应结、平台佣金划拨与推广佣金三种应结成分。

例：给商家 151 开通结算（五步）

  1. 业务主体绑定：账户与协议 → 新增业务主体绑定。业务来源选 jiazheng（生活服务商家），业务主体编号填 151（可用弹窗里的「商家目录搜索」输入 151 直接找到商家），法律主体标识起一个法人代号（如 bianxi）→ 保存草稿 → 另一位授权人员复核批准。以后商家 151 的每一笔订单都归到 bianxi 名下。
  2. 机构收款账户：给主体 bianxi 准入机构账户（支付机构 / 环境 / 商户号 / 资金合同号，勾选已核验能力）→ 复核批准。
  3. 商户结算协议：主体 bianxi × 业务 jiazheng × 站内收银台，计算方式按合同（如比例佣金），履约确认=客户验收确认 → 复核批准。
  4. 结算规则：结算规则 → 新建规则，选业务与主体，配置自动结算或审核后结算及金额区间 → 审核发布。
  5. 验证：商家 151 的新订单完成履约（客户验收）后，「应结与付款」出现该主体的应结明细；收款方对账单按出账周期自动生成。

预订商家（民宿/长租）同理：业务来源选 booking，履约确认固定为按订单离店日期，在结算规则里配置离店等待天数与账单日。

3. 结算规则：逐笔 / 审批 / 账单日（T+N）

「结算规则」按 业务 × 主体 × 渠道 × 金额区间 配置，优先级高者生效，同级冲突会阻止自动结算。模式：自动结算 AUTO / 审核后结算 REVIEW / 暂停 HOLD。草稿由另一位授权人员「审核发布」后生效。

三业务的时间口径不同：下面的「离店等待天数 / 账单日」仅适用预订（民宿/长租）。生活权益（券）核销即资格、生活服务客户验收即资格，等待时间在商户结算协议上配「履约后结算等待（小时）」；外部小程序渠道（生活服务）没有本站资金动作，建议常态配置「审核后结算」仅作对账纪律。

预订（民宿/长租）的时间口径

  • 离店后等待天数 N（必填，0–3650）：按订单锁定离店日期 + N 个北京自然日取得结算资格。
  • 账单日 billing_day（选填，每月 1–28 日）：不填 = 逐笔，每笔订单资格后各自可结算；填写 = 账单日模式，订单在资格后统一等到最近一个账单日，随账单批量结算——这就是 T+N 的账期含义。
逐笔（不填账单日）账单日（如每月 25 日）
可结算时间离店 + N 当日max(离店+N, 最近账单日)
资金动作每笔独立授权/付款账单日集中授权/付款，避免逐笔滚动
出账周期自然月上个账单日 00:00 → 本账单日 00:00，账单日 08:00 自动出账

账单日是结算规则的单一数据源：出账周期由系统按主体自动派生，无需另配。

规则发布/停用时，尚未占用资金的明细会按当前已批准规则即时重估最早付款时间；已进入执行或已付款的事实保留不变。

4. 日常资金运营：应结 · 调整 · 审批 · 执行

  • 应结与付款：列表按 进度（草稿→审核中→已授权→执行中→已付）与「最早付款时间」管理；未到时间不会打开审批或授权。每笔应结由成分构成：商户应结（merchant）/ 平台佣金划拨（platform_transfer）/ 推广佣金（promoter），各自独立授权与付款。
  • 单笔调整分两类：付款安排（金额/时间/账户，不改应结总额）与应结权益变更（补付/减免，必须填依据并重走审批）。改期不得早于离店+N（或账单日）。
  • 审批待办：多节点会签/或签按序推进；平台佣金划拨与商户款联动受控（勾选联动释放的必须同时授权）。
  • 执行：创建执行计划 → 机构队列 → 回执确认；「结果待查询（UNKNOWN）」只能查原单，禁止重试或换号；退票/失败释放按页面指引处理。
  • 补差与赔付：仅登记已核验的独立自有资金；客户赔付审批通过并实际付款后才形成可追偿金额。

5. 对账与出账

  • 出账周期：自然月（缺省）或账单日周期；主体有新订单/义务后系统自动登记出账策略，账单日 08:00 自动出账，也可手动「生成账单」。
  • 账单版本：同一账期内容变化生成新版本，历史版本保留；核验进度（已核对/待处理/存在差异）与资料覆盖（齐全/待补）逐版标注。
  • 外部对账资料（生活服务）：外部小程序渠道的收款/退款/履约/佣金到账由商户报送（自助提交或 CSV 批量导入）或平台导入，另一位复核人核验后才计入已核验金额；核验后的佣金按应收/应付入账并可出具覆盖报告。外部渠道仅对账，不产生本站付款。
  • 生活权益（券）：有效核销即进入账单成分，无需外部凭证；演示券永不出账（见红线）。
  • 差异处理：收款方提出异议 → 独立复核关闭；金额修正必须另行批准调整，不倒改已出账单。

6. 边界与红线

  • 线下/外部渠道只作对账资料，不在结算工作台发起付款。
  • 演示数据（带 is_demo 标记的演示券包、演示订单）永不进入资金域与结算账单。
  • 收款账户必须经机构准入且属于受益主体；缺少已核验能力的动作（代付/释放等）保持关闭。
  • 机构结果未知 = 查原单；失败重试受控（≤3 次）且沿用原请求编号。
  • 所有出金都要求有效资金授权；规则停用/版本变化会使未使用的授权失效。

1. 从入驻到结算的链路

提供资质与结算信息→平台录入主体绑定 / 结算协议 / 收款账户→双人复核批准→订单进入结算

商户侧不需要自己操作系统录入：法律主体标识、机构收款商户号、佣金与履约口径由平台方在「统一结算工作台 → 账户与协议」录入并复核。生活权益商户（券）、生活服务商户与预订商户（民宿/长租）均走同一条链路。你拿到的是两个入口：收款方对账单（看账、确认、异议、下载）与本手册。

2. 我的钱什么时候到（逐笔 / 账单日）

平台与你在合同里约定结算节奏，对账单页顶部的「出账周期」会写明你适用哪种：

节奏规则举例（民宿/长租）
逐笔 T+N每笔订单在离店日后 N 天各自取得结算资格，随即可付（或按合同进入人工审核）离店 10 月 1 日、N=3 → 10 月 4 日起可结算
账单日模式资格日后等到最近一个账单日，随当期对账单批量结算资格日 10 月 4 日、账单日每月 25 日 → 10 月 25 日随账单结算
生活权益（券）客户核销券即按核销入账（可含协议约定的等待小时），出账按对账周期客户 10 月 2 日核销 → 该笔进入当期账单，按出账周期结付
生活服务客户验收确认后取得结算资格；站内收银台渠道可结算，外部小程序渠道仅对账（资金在渠道侧，平台按报送+核验出账）客户 10 月 2 日确认服务完成 → 10 月 2 日起可结算（站内渠道）
  • 预订订单按下单锁定的离店日期计算，不要求客户点击确认。
  • 存在退款/取消的订单会先冻结结算，由平台核验净履约金额。
  • 渠道/推广佣金在平台佣金到账后单独支付，不占用你的应结款。

3. 对账单怎么用

  • 列表：按账期列出每版账单，关注「核验进度 / 资料覆盖 / 发布状态」三个徽标。
  • 明细：逐行展示订单（品类：民宿/长租；入住/离店；下单房费与锁定佣金）、平台结付与外部流水；标注「待补凭证/待复核」的行不计入已核验合计。
  • 确认账单：确认展示内容，不代表资金已到账。
  • 提出异议：指明明细与凭证提交；处理结论由平台独立复核给出，金额修正不倒改已出账单。
  • 下载：CSV / XLSX / PDF 三种格式，含账单汇总与逐笔明细。

4. 常见问题

为什么我看不到某个主体/账单？ 账号的数据权限按主体授权，仅显示授权范围内主体；需要扩大范围请联系平台管理员在账号中心调整。

「金额待补」是什么意思？ 该笔记录还没有可核验的金额凭证，未按零元计入合计；补齐资料并核验后会生成新的账单版本。

状态怎么看？ 待补凭证 / 待复核 = 资料在途；已核验 = 可计入；存在差异 = 有冲突需处理；已出账 = 账单已发布。

换了收款账户怎么办？ 联系平台办理机构结算账户变更，通过复核后新订单使用新账户；在途款按原单查询结果。

生活服务外部小程序的收款，为什么不能在工作台付款？ 外部渠道的钱在渠道侧结算，平台只做对账：由你报送（或平台导入）收款/退款流水，平台独立复核后计入账单与佣金口径，不会替渠道发起付款。

统一结算工作台 → 收款方对账单 → 全站导航总览 → 本手册描述当前原型实现；资金与权限校验均在服务端。
